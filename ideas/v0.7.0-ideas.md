# v0.7.0 — Git Step

## Objectif

Transformer la step Git (actuellement en données mock) en une interface Git entièrement fonctionnelle : staging/unstaging, commits, gestion des branches, et opérations distantes. L'architecture suit le pattern établi : `GitView` -> store -> `git-service.ts` -> `invoke()` -> commandes Rust.

---

## Principes de design

- **Worktree-aware** — toutes les opérations Git ciblent le `worktreePath` de l'instance active, pas le projet racine.
- **Données réelles uniquement** — plus de mock data dans `GitView.svelte` ; chaque state vient du backend Rust via le store.
- **Hunk-level control** — l'utilisateur peut stager/unstager au niveau fichier ou au niveau hunk individuel.
- **Instance-scoped** — le store Git se réinitialise à chaque changement d'instance active.

---

## Couche Rust (`src-tauri/src/commands/git.rs`)

### Commandes existantes à conserver

- `list_branches` — liste les branches locales (déjà implémenté)
- `validate_git_repo` — valide un chemin comme repo Git (déjà implémenté)
- `git_status` — retourne les fichiers modifiés avec leur catégorie (déjà implémenté)

### Nouvelles commandes à ajouter

**Diff**
- `git_diff_unstaged(worktree_path)` — diff des fichiers non stagés (git diff)
- `git_diff_staged(worktree_path)` — diff des fichiers stagés (git diff --cached)
- `git_diff_file(worktree_path, file_path, staged)` — diff d'un fichier spécifique

**Staging**
- `git_stage_file(worktree_path, file_path)` — stage un fichier entier
- `git_unstage_file(worktree_path, file_path)` — unstage un fichier entier
- `git_stage_hunk(worktree_path, file_path, hunk_header)` — stage un hunk via `git apply --cached`
- `git_unstage_hunk(worktree_path, file_path, hunk_header)` — unstage un hunk
- `git_stage_all(worktree_path)` — stage tous les fichiers
- `git_unstage_all(worktree_path)` — unstage tous les fichiers

**Commit**
- `git_commit(worktree_path, message)` — crée un commit avec le message donné
- `git_amend_commit(worktree_path, message)` — amend le dernier commit

**Branches**
- `git_current_branch(worktree_path)` — retourne la branche courante
- `git_checkout_branch(worktree_path, branch_name)` — change de branche
- `git_create_branch(worktree_path, branch_name, from_branch)` — crée une nouvelle branche
- `git_delete_branch(worktree_path, branch_name)` — supprime une branche locale
- `git_list_remote_branches(worktree_path)` — liste les branches distantes

**Remote**
- `git_push(worktree_path, remote, branch, set_upstream)` — push avec option --set-upstream
- `git_pull(worktree_path, remote, branch)` — pull/fetch + merge
- `git_fetch(worktree_path)` — fetch sans merge

**Historique**
- `git_log(worktree_path, limit)` — retourne les N derniers commits (hash, author, date, message)
- `git_log_file(worktree_path, file_path, limit)` — historique d'un fichier spécifique

**Structures de données Rust à définir :**
```rust
pub struct GitDiffHunk {
    pub header: String,      // "@@ -14,7 +14,11 @@"
    pub lines: Vec<DiffLine>,
}

pub struct DiffLine {
    pub kind: String,        // "add" | "remove" | "context"
    pub content: String,
}

pub struct GitFileDiff {
    pub file_path: String,
    pub hunks: Vec<GitDiffHunk>,
}

pub struct GitCommit {
    pub hash: String,
    pub short_hash: String,
    pub author: String,
    pub date: String,        // ISO 8601
    pub message: String,
}
```

## Service TypeScript (`src/lib/services/git-service.ts`)

Seule couche autorisant les appels `invoke()`. Miroir des types Rust.

```typescript
export type DiffLine = { kind: 'add' | 'remove' | 'context'; content: string };
export type GitDiffHunk = { header: string; lines: DiffLine[] };
export type GitFileDiff = { filePath: string; hunks: GitDiffHunk[] };
export type GitCommit = { hash: string; shortHash: string; author: string; date: string; message: string };
export type GitFileStatus = Record<string, 'staged' | 'modified' | 'untracked' | 'deleted'>;
```

Fonctions exportées : `getStatus`, `getDiffUnstaged`, `getDiffStaged`, `getDiffFile`, `stageFile`, `unstageFile`, `stageHunk`, `unstageHunk`, `stageAll`, `unstageAll`, `commit`, `amendCommit`, `getCurrentBranch`, `listBranches`, `checkoutBranch`, `createBranch`, `deleteBranch`, `push`, `pull`, `fetch`, `getLog`.

## Store (`src/lib/stores/git.ts`)

Store réactif centralisé pour la step Git, lié à l'instance active.

**State :**
```typescript
{
  status: GitFileStatus,
  stagedDiffs: GitFileDiff[],
  unstagedDiffs: GitFileDiff[],
  currentBranch: string,
  branches: string[],
  log: GitCommit[],
  commitMessage: string,
  isLoading: boolean,
  error: string | null,
}
```

**Actions exposées :** `refreshStatus`, `stageFile`, `unstageFile`, `stageHunk`, `unstageHunk`, `stageAll`, `unstageAll`, `commit`, `push`, `pull`, `checkoutBranch`, `createBranch`.

**Lifecycle :** subscribe à `activeInstance` — refresh automatique quand l'instance change. Refresh après chaque opération mutante.

## Composants (`src/lib/components/git/`)

### `GitView.svelte` — refacto complet

Remplace les données mock par le store Git. Layout en 3 colonnes :
- Colonne gauche : liste des fichiers unstaged avec statut (modifié, nouveau, supprimé)
- Colonne centrale : liste des fichiers stagés
- Colonne droite : diff du fichier sélectionné + zone de commit

### `GitFileList.svelte` — nouveau

Liste de fichiers avec leur statut. Props : `files: { path: string; status: string }[]`, `onSelect`, `onStageAll`/`onUnstageAll`. Icônes colorées par statut (modifié = jaune, nouveau = vert, supprimé = rouge).

### `GitDiffView.svelte` — nouveau

Affichage du diff d'un fichier. Props : `diffs: GitFileDiff`, `staged: boolean`. Render ligne par ligne avec coloration syntaxique via `tok()`. Boutons par hunk : "Stage hunk" / "Unstage hunk".

### `GitCommitPanel.svelte` — nouveau

Zone de commit en bas de l'interface :
- Textarea pour le message de commit (avec placeholder conventional commit)
- Indicateur du nombre de fichiers stagés
- Bouton "Commit" (désactivé si aucun fichier stagé ou message vide)
- Bouton "Amend" pour modifier le dernier commit

### `GitBranchPanel.svelte` — nouveau

Panneau de gestion des branches (accessible via un bouton dans l'en-tête de la step) :
- Branche courante mise en avant
- Liste des branches locales avec option de switch
- Bouton "Nouvelle branche" avec input de nom
- Bouton "Supprimer" sur les branches non-courantes

### `GitRemotePanel.svelte` — nouveau

Panneau pour les opérations distantes :
- Statut push/pull (X commits ahead, Y commits behind)
- Bouton "Push" avec gestion du cas "pas d'upstream" (propose --set-upstream)
- Bouton "Pull"
- Bouton "Fetch"

### `GitHistoryView.svelte` — nouveau

Vue historique accessible via un onglet dans GitView :
- Liste des commits avec hash court, auteur, date relative, message
- Sélectionner un commit affiche son diff dans `GitDiffView`

## Intégration avec l'instance

L'instance a un champ `branch` déjà présent dans l'en-tête du workspace. À la création d'une instance :
- Si aucune branche n'est assignée, proposer d'en créer une depuis le `ticketId` (ex: `feat/PROJ-42`)
- La branche sélectionnée dans `GitBranchPanel` met à jour `instance.branch` via `instance-service`

## Dépendances Rust

La dépendance `git2` est déjà utilisée dans `git.rs`. Les nouvelles commandes de diff et de staging pourront utiliser `git2` pour la lecture et `std::process::Command` pour `git apply --cached` (staging de hunks partiels — plus simple via CLI que l'API git2).

## Ordre d'implémentation suggéré

1. Commandes Rust : `git_diff_unstaged`, `git_diff_staged`, `git_diff_file` + structs
2. Service TS + types miroir
3. Store `git.ts` avec `refreshStatus` + diffs
4. `GitView.svelte` — remplacer le mock par le store (affichage lecture seule d'abord)
5. Staging fichier entier (Rust + store + UI)
6. `GitCommitPanel` + commande `git_commit`
7. Staging au niveau hunk
8. `GitBranchPanel` + commandes branches
9. `GitRemotePanel` + push/pull
10. `GitHistoryView` + `git_log`
